# 아키텍처와 신뢰 경계

FurnitureDefinition → Canvas2D 가구 renderer → 편집 화면·미디어 출력, RoomDocument → 배치·충돌 규칙 → Canvas2D 방 renderer → 화면·PNG 출력 순서로 구성한다. 렌더러는 Google, 계정, 네트워크를 알지 않는다. 외부 데이터 소스는 정본 데이터를 만들거나 저장하는 어댑터일 뿐이다.

## 예정 구조

- app: 화면과 상호작용
- lib/room: 방 스키마, 검증, 방 코드
- lib/renderer: 투영과 Canvas 렌더러
- lib/furniture: 파라메트릭 가구
- lib/style-packs: 팔레트·조명·재질
- lib/adapters: 로컬 파일·공개 시트 등 선택 연동

## 기본 모드

로그인과 네트워크 요청이 없다. 편집은 브라우저 메모리에서 수행하고 사용자가 명시적으로 방 코드, JSON, PNG를 내보낸다.

## Furniture Foundry

FurnitureDefinition → 조립 셀 정렬 → Canvas2D 아이소메트릭 렌더러 순서로 동작한다. `placement`는 입체(`volume`), 바닥(`floor`), 벽(`wall`) 중 하나이며, 바닥과 벽 셀은 큐브가 아니라 얇은 표면으로 렌더링한다. 편집 중 가구 데이터는 브라우저 메모리에만 있고, 사용자가 공유를 눌렀을 때만 FURN1 코드 또는 URL fragment(#)를 만든다. 실제 사용한 최근 10색은 편의를 위해 기기 로컬 저장소에만 보관하며 UI에서 삭제할 수 있다. URL fragment는 HTTP 요청에 포함되지 않으며 별도의 서버 저장소나 계정 연결을 요구하지 않는다.

가구 데이터는 렌더러와 분리되어 같은 FURN1 코드와 rendererVersion이 같은 결과를 만들 수 있어야 한다. 방 배치기가 가구를 소비할 때도 완성된 FurnitureDefinition을 하나의 오브젝트로 취급한다.

공방의 확대율·화면 이동·활성 도구·선택 영역·실행 취소 기록은 편집 세션의 일시적 상태다. `lib/furniture/editing.ts`의 순수 함수가 격자 크기 변경, 영역 이동·복제·회전·반전, 채우기와 삭제를 FurnitureDefinition 입력에서 결정론적으로 계산하고, React 화면은 결과 스냅샷을 최대 80단계 메모리에만 보관한다. 격자를 줄여 잘린 셀도 실행 취소로 복원할 수 있으며 이 기록은 FURN1과 RoomDocument에 포함하지 않는다.

다면 편집은 별도 정본을 만들지 않는다. 아이소메트릭과 평면은 x·y, 정면은 x·z, 측면은 y·z 편집면으로 같은 FurnitureDefinition 좌표를 투영한다. 입체 가구는 각 보기의 수직축에 해당하는 층·깊이·가로 단면 하나를 편집하고, 바닥은 평면, 벽은 정면을 직교 보기로 제공한다. 화면 투영과 포인터 역투영만 보기별로 달라지며 저장 데이터는 그대로다.

### 미디어 내보내기

`FurnitureDefinition → 배치용 표면 메시 → 투명 Canvas → PNG/WebP/스프라이트 시트` 순서를 사용한다. 공방 편집 격자를 캡처하지 않고 Room Composer와 같은 완성 가구 메시 렌더러를 재사용한다. 크기, 보기 방향, 배경, 외곽선·재질 경계, 그림자는 내보내기 옵션이며 FurnitureDefinition을 변경하지 않는다. 다운로드는 사용자 클릭으로만 시작하며 Blob URL은 사용 직후 폐기한다.

정적 PNG와 WebP, 입체·바닥 가구의 4방향 PNG 시트를 첫 단계로 제공한다. GIF와 애니메이션 WebP는 동일한 프레임 렌더러에 라이선스가 확인된 로컬 인코더를 연결한 뒤 제공한다. 벽 소품은 회전 시트보다 단일 투명 이미지가 기본이다.

### 로컬 이미지 변환

향후 이미지 입력은 File API와 메모리 Canvas에서만 디코드한다. 축소 크기, 팔레트 수, 투명도 임계값과 디더링을 사용자가 고르고, 결과를 픽셀 패널·높이 부조·삼면도 실루엣 중 하나로 명시적으로 변환한다. 원본 파일, EXIF, 파일 경로를 FurnitureDefinition이나 분석 로그에 넣지 않는다. 고밀도 팔레트 표면은 셀마다 RGB를 반복하지 않고 팔레트 인덱스와 구간 압축을 사용하는 다음 스키마에서 다룬다.

조립 해상도 `resolution`은 현재 1× 또는 2×다. 2× 셀은 방 좌표에서 한 변이 1× 셀의 절반이므로, 1× 가구를 세분화해도 실제 배치 크기는 유지된다. 2×에서 1×로 낮출 때는 같은 상위 셀의 재료와 색을 빈도·문자열 순서로 결정해 결과가 항상 같게 한다. 4× 이상의 편집 해상도는 sparse/chunk 저장과 다음 공유 스키마의 크기 제한을 설계한 뒤 추가한다.

## Room Composer

RoomDocument의 `furniture` 오브젝트는 FURN1에서 검증한 FurnitureDefinition 전체를 포함하고 위치, 회전, 벽 방향만 별도로 가진다. 방 Canvas는 입체 가구를 깊이 정렬하고, 바닥 소품은 얇은 바닥 면으로, 벽 소품은 선택한 뒤쪽·왼쪽 벽의 평면으로 렌더링한다. 편집 상태는 메모리에만 있으며 사용자가 방 코드 복사를 눌렀을 때 커스텀 가구 배치가 ROOM1에 포함된다. 계정·서버 저장·네트워크 요청은 추가하지 않는다.

## 공개 시트 모드

읽기 전용이며 공개 가능한 전용 시트만 사용한다. 시트 ID는 비밀로 취급하지 않고 원본 운영 시트나 개인정보 열을 노출하지 않는다.

## 인증 연동

비공개 시트 자동 읽기 또는 쓰기는 계정 보안 기능이다. 별도의 위협 모델, 권한 최소화, 토큰 취소 절차가 준비될 때만 구현한다.

## provenance

모든 스타일 팩은 팩 ID·버전, 원안 작가와 구현자, 라이선스, 포함 에셋 출처, 생성형 이미지 모델 사용 여부를 가진다.
